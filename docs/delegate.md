## Delegation

_Delegation_ is a way to participate in the _cooperative consensus_ on the Proxima ledger **without the need of running a sequencer**. 

If you are not running a sequencer, you better delegate your funds to a _sequencer_ of your choice. The sequencer then will be able to generate inflation from the delegated tokens for you. 
You will be able to revoke delegated funds in most cases immediately. 
You will be able to revoke your delegated funds unconditionally at least for 10 minutes after the end of the **freeze period** (more below).

The command `proxi node allchains -q` will list all sequencers running in the system and available as a delegation target:
The command `proxi node allchains -l` lists all active delegations in the network
The command `proxi node allchains -o [-v]` lists all controllers of delegations and their delegations

The tokens are delegated in the form of the chained output (UTXO) which is controlled by the **delegation lock**. 

The following command will display holdings of the wallet with additional info about the form they take: on usual (non-chain) UTXO, on delegation outputs or on ordinary chain outputs with their status: _frozen_, _unlockable by the owner_ or _on hold_.

`proxi node balance` or `proxi node balance -v`

To delegate your tokens to the sequencer `<target sequencer ID>` use command:

`proxi node delegate amount <amount>` delegates specified amount to optimal, randomly selected sequencer. This is preferred default

Command `proxi node delegate amount <amount> [-q <target sequencer ID>] [-e <max number of freeze epochs>]` with optional flags allows to specify particular target sequencer and/or maximum frozen epochs `<max number of freeze epochs>` sets maximum number of consecutive epochs the sequencer can freeze the delegated amount output (the _freeze period_).

1 delegation epoch is 530 slots (~1.5 hours). Default is maximum possible - 8 epochs (~12 hours).

The command will create a delegation output with the tokens and the _delegation lock_. Few slots later sequencer will consume and freeze the delegation output.
Before freezing, sequencer will add future calculated inflation amount to the delegation output as a so-called **delegation advance**. 
That will be a sequencer's "investment" into the delegation. The return on this investment will be excess inflation generated by the sequencer from the frozen funds during the freeze period.

If status of the delegation is `frozen`, the UTXO can only be consumed by the target sequencer and only for the purpose to unfreeze it.

The command `proxi node delegate askstop <delegation ID>` will send a securely authenticated request to the sequencer to stop the delegation.
The honest sequencer will immediately unfreeze the delegation, and it will appear in the status `on hold`. 
Note that sequencer is centralized and trusted entity, so in theory it can ignore (censor) you `askstop` requests. In the worst scenario sequencer will delay its inflation
until funds auto-unfreeze in end of the freeze period. That, however can cost the sequencer its reputation: the token holder would avoid it in the future.   

There's another nuance with unfreezing: the sequencer has invested tokens into the delegation upon freezing it by adding _delegation advance_.
Returning the delegation back to the owner before freeze period ends would mean part of the investment lost for the sequencer. 
Therefore, to compensate for that loss, the command `proxi node delegate askstop <delegation ID>` will put calculated amount of compensation to the _tag-along_ output of the request transaction. This will require at least the compensation amount in the wallet. Sequencer will rightfully ignore (censor) the `askstop` request which will mean loss to it. 

What will happen if the wallet has not enough funds for compensation? In that case it will not be possible to take back delegation until the end of the freeze period. 

In either case, immediately after the freeze period delegation auto-unlocks. The repetitive freezing will be prevented **safe revocation slots** (60 slots, ~10 min). 
During those slots only owner of the funds can consume the output and use the funds the way she likes.

Whenever status of the delegations is not `frozen`, owner can do one of the following
- discontinue the delegation with the command `proxi node killchain <delegation ID>`. In that case all funds will be returned to the ordinary ED25519-address locked output
- continue the delegation with the command `proxi node delegate chain <delegation ID> [-e <max delegation epochs>]` by sending `on hold` chain to the same or any another sequencer.

Command `proxi node delegate status <delegation ID> [-v]` will display information about the particular delegation output.
